Fare computation logic:

Fare is based on the pickup point area relative to the drop-off point area — NOT GPS distance
If a commuter travels from Point 33 toward Point 4, but the actual drop-off is between Point 4 and Point 5, the conductor selects the nearest official operational point area (Point 4 = SM Marilao) for fare computation
The conductor manually selects the operational point area during transaction processing

REVISION 4: UPDATE REAL-TIME TRACKING OPTIMIZATION LOGIC
Commuters should NOT continuously view all active CHATCO units system-wide
Real-time unit visibility should only activate when a CHATCO unit is within a 1-kilometer radius of the commuter's current location
Nearby unit detection should trigger a sound notification informing the commuter that a nearby CHATCO unit is approaching
This improves: optimization, reduced unnecessary map rendering, lower bandwidth usage, reduced system load, fewer synchronization and real-time tracking issues
