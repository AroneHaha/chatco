[None] Laravel + Supabase  |  Sanctum Auth  |  GCash Direct QR  |  GPS + Hail System
[Heading 2] Executive Summary
[None] This roadmap covers 9 backend-only sprints from June 16 to August 15, 2025, targeting production readiness for the Chatco jeepney tracking system. The frontend (Next.js) is already implemented; this plan exclusively addresses the Laravel backend that the frontend expects to connect to.
[None] Key architectural decisions confirmed throughout all sprints:
[List Paragraph] Wallet system is fully and permanently removed — no internal balance, no top-up, no ledger
[List Paragraph] GCash QR is direct external payment via PayMongo only — no internal money movement
[List Paragraph] All jeepney units are visible to commuters at all times — no distance filter on visibility
[List Paragraph] 1KM hail restriction is enforced server-side only — frontend is display-only
[List Paragraph] Backend is the single source of truth — frontend never bypasses backend validation

[Heading 2] Critical Architecture Warnings
[List Paragraph] NEVER deploy with APP_DEBUG=true — full stack traces expose DB structure and server paths
[List Paragraph] The frontend middleware.ts reads the chatco_session cookie role claim client-side — this is display routing only. The backend must ALWAYS re-verify the role via auth:sanctum + role middleware on every request.
[List Paragraph] The gcash-payment.ts service has a sandbox fallback that simulates payments (isSimulated: true). Confirm PAYMONGO_CONFIG.isSandbox = false in production .env — the backend must never trust simulated payment results.
[List Paragraph] shouldUseConductorApi() in the frontend defaults to API mode unless NEXT_PUBLIC_CONDUCTOR_API_MODE=local is set. Confirm this variable is NOT set in production (it would silently disable all conductor API calls).
[List Paragraph] vehicle_locations must be an upsert (INSERT OR UPDATE by vehicle_id), not an append — otherwise the table grows unbounded and GET /api/vehicles/locations returns stale duplicates.
